1. Project Overview

BidFlow AuctionX Tracking is a production-grade, full-stack industrial bid management platform. It enables organizations to manage the complete lifecycle of business bids — from client submission through AI-powered analysis, employee assignment, progress tracking, to final approval and client feedback.

🤖
AI-Powered Analysis
Google Gemini AI for win probability prediction, sentiment analysis, bid summaries, and intelligent recommendations.
🗺️
Live Map Tracking
Real-time location tracking of team members using OpenStreetMap and React Leaflet with geolocation API.
🔔
Real-time Notifications
WebSocket-based instant notifications for every bid action — assignments, approvals, status changes.
🔐
Enterprise Security
JWT authentication, BCrypt password hashing, Google OAuth 2.0, and role-based access control.
💳
Subscription System
4-tier plan system (Free/Basic/Pro/Enterprise) with payment processing and invoice generation.
🌐
Multilingual Support
Full English, Hindi, and Arabic language support with RTL layout for Arabic and persistent preference.

Communication Protocols

REST/HTTP: All CRUD operations use standard HTTP methods (GET, POST, PUT, PATCH, DELETE) with JSON payloads via Axios on the frontend.

WebSocket (STOMP): Real-time bi-directional communication for live notifications and the SSH terminal feature. Spring Boot's WebSocket support handles connection upgrades.

JWT (JSON Web Tokens): Every protected API request carries a signed JWT token in the Authorization header. The backend validates the token on each request via a custom filter chain.

4. Backend — Spring Boot Deep Dive

4.1 Security Layer — JWT Authentication Flow

Every HTTP request passes through a custom JwtAuthFilter before reaching any controller. This filter validates the JWT token, loads the user, and sets the Spring Security context.

1
Client sends request with JWT token
Frontend sends HTTP request with Authorization: Bearer eyJhbGci... header via Axios interceptor automatically.
2
JwtAuthFilter intercepts
Extracts the token from the Authorization header. Supports both real JWT tokens and demo tokens (demo-token-ROLE format for testing).
3
Token validation
JwtUtil validates the signature, checks expiration, and extracts the userId from the token's subject claim using HS256 verification.
4
User loaded from MongoDB
User document is fetched from MongoDB by ID and wrapped in Spring Security's Authentication object with proper role authorities.
5
SecurityContext populated
SecurityContextHolder stores the authenticated user. Controllers access it via AuthHelper.getCurrentUser() to get the currently logged-in user.

9. Authentication & Security

🔐 JWT Token Authentication
JSON Web Tokens signed with HS256 algorithm using a 256-bit secret key. Token carries userId as subject, expires in 7 days (604,800,000ms). Validated on every request by JwtAuthFilter.
🔒 BCrypt Password Hashing
All passwords hashed using BCrypt with cost factor 12 — providing ~200ms hash time to resist brute-force attacks. Passwords are never returned in any API response.
🌐 Google OAuth 2.0
Full OAuth2 redirect flow. Users click "Sign in with Google" → redirected to Google → callback creates/links account → returns same JWT token as regular login.
🛡️ Role-Based Access Control
Spring Security method-level security with @PreAuthorize annotations. Each endpoint checks the authenticated user's role before processing the request. 4 roles with granular permissions.
🔄 CORS Configuration
Cross-Origin Resource Sharing configured to allow requests only from trusted frontend origins (localhost ports in dev, *.onrender.com in production). Uses pattern matching for wildcard support.
📧 OTP Email Verification
6-digit OTP sent via Gmail SMTP using Spring Mail. OTP tokens stored in MongoDB with TTL expiry. Used for forgot password flow and account verification.
